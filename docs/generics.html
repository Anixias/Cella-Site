Generics

A generic declaration takes types as parameters. One generic function or record works for every type you give it, and the compiler builds a separate copy of it for each type it's used with. This chapter covers generic functions, records and enums, the constraints that say which types a parameter accepts, and value parameters, which take compile-time integers instead of types.

Generic functions

Type parameters go in brackets after the function's name. Inside the function, a type parameter is a type like any other:

pick[T]: fun(useFirst: bool, a: T, b: T) -> T{	if useFirst		ret a 	ret b} main: fun{	val number = pick(true, 1, 2)	val ratio = pick(false, 1.5, 2.5)	val text = pick[cstr](true, "yes", "no")	printf("%d %.1f %s\n", number, ratio, text)}
Output
1 2.5 yes

pick takes its values without a mode, so it gets them by value: a copy for a T that copies, and the value itself for one that has to move. Generic code that keeps using a T after passing it on needs every T to be copyable, which the type parameter says with T: copy (see Constraints). See Parameter modes for what imm and mut mean.

Type arguments

A call can write its type arguments in brackets, as pick[cstr] does above. Usually it doesn't need to: the compiler infers them from the arguments, and when the arguments don't settle them, from the type the call's result is expected to have:

identity[T]: fun(value: T) -> T => value main: fun{	val a = identity(5)	val b: i64 = identity(6)	val c = identity[u8](7)	printf("%zu %zu %zu\n", sizeOf(a), sizeOf(b), sizeOf(c))}
Output
4 8 1

When several arguments share a type parameter, the type they all convert to wins. A literal fits whatever type the other arguments give it, and two integer types widen to the larger one:

main: fun{	val small: i32 = 3	val large: i64 = 4000000000	val wide = pick(false, small, large)	val mixed = pick(true, 1, 2.5)	printf("%lld %.1f\n", wide, mixed)}
Output
4000000000 1.0

Here wide is an i64 and mixed is an f64. When nothing settles a type parameter, or the arguments disagree, or the call writes the wrong number of type arguments, the call is an error:

make[T]: fun -> usize => sizeOf(T) same[T]: fun(a: T, b: T) -> i32 => 0 main: fun{	val a = make()Cannot infer 'T' for 'make'	val b = same(1, true)Cannot convert type 'integer literal' to 'bool'	val c = make[i32, i64]()'make' takes one generic argument}

How generic bodies are checked

A generic body is checked once, where it's declared, against what every possible T allows, so its errors show up there and not at the calls. Without constraints, that means generic code can move a T, borrow it, store it in fields and arrays, point to it and ask for sizeOf(T), but it can't call methods or operators on it:

add[T]: fun(imm value: T) -> T => value + 1No operation defined for '+' between 'T' and 'integer literal' main: fun{	val x = add(2)}

Calling add(2) with an i32 doesn't help, since the body has to work for every type. To use operators and methods on a T, give it a trait bound.

Each type a generic is used with gets its own compiled copy, with its own layout and code. A generic function that calls itself with a bigger type each time would need endless copies, which is an error:

Box[T]: rec{	value: T} nest[T]: fun(value: T, depth: i32) -> i32{	if depth == 0		ret 0 	ret nest(Box(value), depth - 1)Instantiating 'nest' never ends} main: fun{	val levels = nest(1, 3)}

Generic and plain overloads

A generic function can share its name with plain functions and other generic ones. A call goes to the plain overload when the argument already has the type its parameter takes. Otherwise the generic overload, which takes any type as it is, wins over a plain one that would need a conversion:

describe: fun(value: i32) -> cstr => "plain" describe[T]: fun(imm value: T) -> cstr => "generic" main: fun{	val small: u8 = 4	printf("%s %s %s\n", describe(5), describe(imm small), describe(true))}
Output
plain generic generic

describe(imm small) passes the u8 to the generic overload rather than converting it to an i32. Overloads follow the usual rules from Functions. Two generic overloads that differ only in the names of their type parameters have the same signature:

same[T]: fun(imm x: T) -> i32 => 1'same' is declared more than once with the same signaturesame[U]: fun(imm x: U) -> i32 => 2'same' is declared more than once with the same signature

Generic records

Records take type parameters the same way. Fields, constructors, methods and destructors can all use them. A type argument can be written, as in Pair[u8, bool], or inferred from the constructor's arguments:

Pair[A, B]: rec{	first: A	second: B 	swapped: fun(self) -> Pair[B, A] => Pair(self.second, self.first)} main: fun{	val p = Pair(1, 2.5)	val q = Pair[u8, bool](7, true)	val r = p.swapped()	printf("%d %.1f | %d %d | %.1f %d\n", p.first, p.second, q.first, q.second, r.first, r.second)	printf("%zu %zu\n", sizeOf(Pair[u8, bool]), sizeOf(Pair[i64, u8]))}
Output
1 2.5 | 7 1 | 2.5 1
2 16

Each instantiation is its own type with its own layout, as the sizes show: a Pair[u8, bool] takes 2 bytes and a Pair[i64, u8] takes 16.

Static functions and static fields are reached through an instantiation, as in Counted[i32].made. Every instantiation has its own copy of each static field:

Counted[T]: rec{	value: T	made: var i32 = 0 	new: op(value: T)	{		self.value = value		made += 1	}} main: fun{	val a = Counted(1)	val b = Counted(2)	val c = Counted(true)	printf("%d %d %d\n", Counted[i32].made, Counted[bool].made, Counted[f64].made)}
Output
2 1 0

Generic methods

A method or static function can take type parameters of its own, beside its type's. Here map turns a Cell[T] into a Cell[U], with U inferred from the function it's given or written out:

Cell[T]: rec{	value: T 	map[U]: fun(self, imm change: fun[T -> U]) -> Cell[U] => Cell(change(self.value))} half: fun(value: i32) -> f64 => f64(value) / 2.0 main: fun{	val whole = Cell(5)	val halved = whole.map(half)	val tripled = whole.map[i64](fun(value) => value * 3)	printf("%.1f %lld\n", halved.value, tripled.value)}
Output
2.5 15

Function types and lambdas are covered in Function values and closures.

Generic enums

Enums take type parameters too, which is how an optional value or a result can be written once for every type:

Option[T]: enum{	none	some(value: T) 	isSome: fun(imm self) -> bool => self is some(_)} find: fun(values: array[i32, 4], target: i32) -> Option[usize]{	for i in 0..values.length	{		if values[i] == target			ret some(i)	} 	ret none} main: fun{	val values = [4, 8, 15, 16]	val found = find(values, 15)	val missing = find(values, 3)	if found is some(val index)		printf("found at %zu\n", index) 	printf("%d %d\n", found.isSome(), missing.isSome())	val explicit = Option[f64].some(0.5)	val inferred = Option.some(true)	printf("%zu %zu\n", sizeOf(explicit), sizeOf(inferred))}
Output
found at 2
1 0
16 2

Where the enum type is known, as in ret some(i), a bare case name is enough. A case can name its arguments, as in Option[f64].some(0.5), or leave them to be inferred, as in Option.some(true). Cases and matching are covered in Enums and Pattern matching.

Constraints

A constraint after a type parameter's name limits the types it accepts, and in return lets the generic code do more with it. [T: copy] accepts only types that can be copied, so the body can copy a T:

Pair[T]: rec{	a: T	b: T} Point: rec{	x: i32	y: i32} twin[T: copy]: fun(value: T) -> Pair[T] => Pair(value, value) main: fun{	val numbers = twin(7)	val points = twin(Point(1, 2))	printf("%d %d %d\n", numbers.a, numbers.b, points.b.y)}
Output
7 7 2

A type argument that doesn't meet a constraint is an error where it's used. Inside other generic code, a type parameter meets a constraint only if its own constraints say so:

Token: own rec{	id: i32 	drop: op	{	}} twin[T: copy]: fun(value: T) -> i32 => 1 forward[T]: fun(imm value: T) -> i32 => twin(value)'twin' requires 'T: copy''T' can't be copied main: fun{	twin(Token(1))'twin' requires 'T: copy''Token' can't be copied}

Several constraints are joined with +, as in [T: copy + noref]. Each one can appear only once in a list, and some can't be combined:

both[T: copy + drop]: fun -> i32 => 0Cannot combine 'copy' and 'drop'Cannot combine 'copy' and 'drop' twice[T: copy + copy]: fun -> i32 => 0'copy' is required more than once'copy' is required more than once

The constraints are:

ConstraintAccepts
copytypes that can be copied
noreftypes that hold no borrows
droptypes with a destructor
defaulttypes whose all-zero value is valid
new, new(...)types with a matching constructor
nulltypes that have a null value
exttypes that can cross into C
atomictypes the target can access atomically
a traittypes that implement the trait
a function typefunctions and closures of that type

ext is covered in Calling C, atomic in Atomics, trait bounds in Traits and function types as constraints in Function values and closures.

copy

A type can be copied when it isn't declared own and everything it holds can be copied (see Ownership and destructors). T: copy lets a val copy a T and lets the code use a T after passing it on.

noref

A type holds borrows when it is a borrow type like imm[i32], a str, a ref rec or ref enum, or anything that contains one (see Borrows). T: noref accepts only types that hold none, which a container that keeps its values needs. Without it, a type parameter may hold borrows, so it can't be passed on to something that requires noref:

Holder[T: noref]: rec{	value: T} Wrapper[T]: rec{	inner: Holder[T]'Holder' requires 'T: noref''T' may hold borrows} main: fun{	val count = 5	val a = Holder(count)	val b = Holder(imm count)'Holder' requires 'T: noref''imm[i32]' holds borrows}

Holder(imm count) would make a Holder[imm[i32]], which holds a borrow.

drop

T: drop accepts only types with a destructor, written or inherited from a field:

Text: own rec{	id: i32 	drop: op	{		printf("drop %d\n", self.id)	}} Labeled: own rec{	text: Text	count: i32} hold[T: drop]: fun(value: T){	printf("holding\n")} main: fun{	hold(Text(1))	hold(Labeled(Text(2), 5))}
Output
holding
drop 1
holding
drop 2
hold[T: drop]: fun(value: T){} main: fun{	hold(5)'hold' requires 'T: drop''i32' has no destructor}

default

T: default accepts types that have a legal default: types whose all-zero memory is a valid value, as Records describes. The body can then declare a T without a value, which starts as zeros, and call T():

Vec2: rec{	x: f32	y: f32} zeroed[T: default]: fun -> T{	var value: T	ret value} main: fun{	printf("%d %.1f %d\n", zeroed[i32](), zeroed[Vec2]().y, zeroed[bool]())}
Output
0 0.0 0

Without the constraint, a T declared without a value has to be assigned before it's read, and a type without a legal default doesn't meet it:

Fixed: rec{	n: i32 	new: op(n: i32)	{		self.n = n	}} zeroed[T: default]: fun -> T{	var value: T	ret value} blank[T]: fun -> T{	var value: T	ret valueCannot use uninitialized values} main: fun{	val f = zeroed[Fixed]()'zeroed' requires 'T: default''Fixed' has no default}

new

T: new asks for a constructor without parameters, and T: new(usize) for one that takes a usize; the generic code then calls it as T() or T(64). A type meets it with a declared constructor that takes exactly those parameter types, or, when it declares no constructor, with its field-by-field constructor or, for new, with T(). Built-in conversions count too, so f64 meets new(usize):

Buffer: rec{	size: usize 	new: op	{		self.size = 16	} 	new: op(size: usize)	{		self.size = size	}} Point: rec{	x: i32	y: i32} make[T: new]: fun -> T => T() sized[T: new(usize)]: fun -> T => T(64) main: fun{	val a = make[Buffer]()	val b = sized[Buffer]()	val p = make[Point]()	val c = sized[f64]()	printf("%zu %zu %d %.1f\n", a.size, b.size, p.x, c)}
Output
16 64 0 64.0

The parameter list can name several types and give each one a mode, as in new(i32, i32), new(imm T) or new(Text, mut i32). Calls pass arguments the way the modes say. A type that has no such constructor doesn't meet the constraint:

Fixed: rec{	n: i32 	new: op(n: i32)	{		self.n = n	}} make[T: new]: fun -> T => T() sized[T: new(usize)]: fun -> T => T(64) main: fun{	val a = make[Fixed]()'make' requires 'T: new''Fixed' has no constructor without parameters	val b = sized[bool]()'sized' requires 'T: new(usize)''bool' has no constructor taking 'usize'}

T: new doesn't promise that zeros are a valid T. A generic body that declares a T without a value needs T: default instead.

null

T: null accepts types that have a null value, such as pointers and cstr. The generic code can then use null as a T and compare a T with it:

empty[T: null]: fun -> T => null isEmpty[T: null]: fun(imm value: T) -> bool => value == null main: fun{	var x = 5	val p: ptr[i32] = empty()	val text = empty[cstr]()	printf("%d %d %d\n", isEmpty(imm p), isEmpty(imm text), isEmpty(@x))}
Output
1 1 0
Nullable[T: null]: rec{	value: T} main: fun{	val n: Nullable[i32] = undef'Nullable' requires 'T: null''i32' has no null}

Value parameters

A value parameter takes a compile-time integer instead of a type. It's declared with const and an integer type, as in N: const usize, and inside the declaration it's a constant: it can size an array, appear in expressions, or be passed on as another generic's argument. Like a type parameter, it's inferred from the arguments or written out:

sum[N: const usize]: fun(values: array[i32, N]) -> i32{	var total = 0	for value in values		total += value 	ret total} zeros[N: const usize]: fun -> array[i32, N]{	var result: array[i32, N]	ret result} main: fun{	printf("%d %d\n", sum([1, 2, 3]), sum([10, 20, 30, 40, 50]))	val four = zeros[4]()	val two: array[i32, 2] = zeros()	printf("%zu %zu\n", four.length, two.length)}
Output
6 150
4 2

Each value gets its own compiled copy, as each type does. Records and enums take value parameters too, mixed with type parameters in any order. A value argument can be any constant expression, such as a named constant times 2:

capacity: const usize = 4 Stack[T: noref, N: const usize]: rec{	items: array[T, N]	count: usize 	push: fun(mut self, value: T)	{		self.items[self.count] = value		self.count += 1	} 	isFull: get(imm self) -> bool => self.count == N} main: fun{	var small = Stack[i32, 2]()	small.push(1)	small.push(2)	var large = Stack[f64, capacity * 2]()	large.push(0.5)	printf("%d %d %zu\n", small.isFull, large.isFull, sizeOf(Stack[u8, 8]))}
Output
1 0 16

A value parameter must have an integer type, and the value given must fit it. Inside a generic argument, a value parameter must stand alone: array[i32, N] works, but array[i32, N + 1] doesn't, while expressions of plain constants, like capacity * 2, still do. A value parameter isn't a type, and a type isn't a value:

grow[N: const usize]: fun(values: array[i32, N]) -> array[i32, N + 1] => undefCannot use arithmetic on value parameters in generic arguments Ratio[N: const f64]: recValue parameters need an integer type{	value: i32} Small[N: const u8]: rec{	items: array[i32, N]} misuse[N: const usize]: fun -> usize{	val x: N = 1'N' is not a type	ret N} main: fun{	val a = Small[300]()'300' doesn't fit in 'u8'	val b = Small[i32]()'i32' is not a constant}

Adding members under bounds

An impl block on a generic type with stronger constraints adds members that exist only for the instantiations that meet them. A block can also name a concrete instantiation, so its members exist only for that one type:

Pair[T]: rec{	a: T	b: T} Pair[T: copy]: impl{	swapped: fun(self) -> Pair[T] => Pair(self.b, self.a)} Pair[i32]: impl{	sum: fun(self) -> i32 => self.a + self.b} main: fun{	val p = Pair(3, 4)	val q = p.swapped()	val r = Pair(1.5, 2.5).swapped()	printf("%d %d %d %.1f\n", q.a, q.b, p.sum(), r.a)}
Output
4 3 7 2.5

Inside Pair[T: copy]: impl, the body knows T: copy, so self can be copied. Using a member on an instantiation that doesn't meet the block's constraints is an error at the use. In the type's own module, a block that adds no constraints to the declaration's is an error, since those members belong in the type's own body:

Token: own rec{	id: i32 	drop: op	{	}} Pair[T]: rec{	a: T	b: T} Pair[T: copy]: impl{	swapped: fun(self) -> Pair[T] => Pair(self.b, self.a)} Pair[i32]: impl{	sum: fun(self) -> i32 => self.a + self.b} Pair[T]: implCannot declare 'impl' blocks that add no bounds{	first: fun(imm self) -> imm[T] => imm self.a} main: fun{	val tokens = Pair(Token(1), Token(2))	val swapped = tokens.swapped()'swapped' requires 'T: copy''Token' can't be copied	val total = Pair(1.5, 2.5).sum()Type 'Pair[f64]' has no member 'sum'}

Blocks like these most often add members under a trait bound. Blocks that implement a trait, and blocks outside the type's own module, are covered in Traits.
